# Repository Structure

This repository follows a lightweight Python project layout with a single core script, an automated test suite, and standard environment configuration files.

```
 photo-datetime-organizer/
├── README.md                # Project documentation, usage guide, and architecture details
│
├── photo_organizer.py       # Core execution script (album scanning, sorting, copying, CSV logging)
│
├── requirements.txt         # Production dependencies for running the organizer
├── requirements-dev.txt     # Development and testing dependencies (e.g., pytest)
│
├── pytest.ini               # Pytest execution configuration
│
└── tests/                   # Test suite directory
    └── test_photo_organizer.py # Unit and integration tests covering metadata extraction & sorting

```

---

## File & Directory Breakdown

### Primary Source Files

* **`photo_organizer.py`**
The main entry point. Scans top-level album subfolders, extracts photo capture dates using EXIF metadata priority (falling back to file timestamps), performs byte-for-byte lossless copies into `<album>Sorted/` directories, and generates the `<album>_image_data.csv` tracking log.

### Configuration & Dependencies

* **`requirements.txt`**
Contains runtime dependencies needed to execute `photo_organizer.py` (e.g., Pillow for EXIF parsing).
* **`requirements-dev.txt`**
Contains development dependencies required to run tests or contribute to the repo (e.g., `pytest`).
* **`pytest.ini`**
Configures test discovery paths, flags, and runner behavior for Pytest.

### Tests & Documentation

* **`tests/test_photo_organizer.py`**
Pytest suite that validates key script functionality:
* Album directory filtering (skipping hidden and `*Sorted` folders).
* Date priority resolution (`DateTimeOriginal` $\rightarrow$ `DateTimeDigitized` $\rightarrow$ `DateTime` $\rightarrow$ file system time).
* Chronological sorting accuracy and original filename tie-breaking.
* Correct output naming formatting (`<album>-<yyyy-mm-dd>-<###>.<ext>`).
* CSV file output structure and record accuracy.


* **`README.md`**
Main developer and user documentation detailing setup, expected folder structures, workflow steps, and test instructions.

---

> **Note on Build Artifacts (`__pycache__/`):**
> Compiled Python bytecode folders (such as `__pycache__/` or `.pyc` files) are automatically generated by the Python runtime during execution. These are local runtime artifacts and should typically be excluded from version control via `.gitignore`.
